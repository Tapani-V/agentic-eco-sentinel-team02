3. ✅ ORCHESTRATOR WORKFLOW
   Client → Orchestrator (8000)
            ├─ Loads real device data from data/generated/
            └─ Forwards to HealthAgent (8001)
               └─ Returns health_status
                  └─ Router Decision:
                     ├─ If healthy → SKIP diagnosis (health_only path)
                     └─ If not healthy → Forward to DiagnosisAgent (8002)
                        └─ Returns confidence + diagnosis
                           └─ Confidence Check:
                              ├─ If ≥0.85 → RULES-BASED (fast, cheap)
                              └─ If <0.85 → LLM-BASED (smart, slower)

4. ✅ AWS MCP TOOL INTEGRATION
   - create-work-order (for URGENT_REPAIR)
   - schedule-maintenance (for SCHEDULE_MAINTENANCE)
   - get-spare-parts (for CHECK_PARTS_FIRST)
   - All verified working with real AWS

5. ✅ LLM DECISION LOGIC
   HealthAgent Confidence = 1.0 (always definitive)
   DiagnosisAgent Confidence:
     ├─ 1.0 = Perfect match to pattern
     ├─ 0.90 = Clear pattern match
     ├─ 0.85-0.89 = Good match
     ├─ 0.50-0.84 = Ambiguous (LLM CALLED HERE)
     └─ <0.50 = Very uncertain

UNDERSTANDING LLM USAGE:
=========================

When LLM is CALLED:
  ✅ Device has issues (not healthy)
  ✅ AND confidence < 0.85 (ambiguous pattern)
  ✅ Cost justified by uncertainty

When LLM is NOT called:
  ❌ Device is healthy (confidence = 1.0)
  ❌ Clear pattern match (confidence ≥ 0.85)
  ❌ Using fast rules-based decision

Cost Analysis:
  - Health-only path: $0, ~26ms
  - Rules-based diagnosis: $0, ~150-300ms
  - LLM-based diagnosis: $0.50-2, ~800-1000ms
  
Optimization:
  - ~80% devices healthy → Only pay for $0 health_only
  - ~15% devices clear patterns → Rules-based $0
  - ~5% devices ambiguous → LLM $0.50-2
  - Overall: ~$100/month LLM cost, prevents $10,000+ failures
